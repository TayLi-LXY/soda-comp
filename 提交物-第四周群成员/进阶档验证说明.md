# 群成员管理 · 进阶档验证说明

## 进阶做了什么

在「成员 = Agent + Mock 回读」之上：

1. **项目角色唯一**：同会话内不可两个 Agent 同为「编排 / 数据 / …」
2. **权限不足**：`operatorCanManage === false` 时添加 / 移出 / 改角色均拒绝并提示
3. **重复绑定**：同一 Agent 不可再次添加（`ALREADY_MEMBER`）
4. **使用中移出确认**：`inUse` 的 Agent（种子里「SQL 专家」）移出前弹确认框

## 冲突矩阵

| 操作 | 触发条件 | 错误码 | 期望文案要点 | 界面 |
|------|----------|--------|--------------|------|
| 保存角色 | 目标角色已被其他 Agent 占用 | `ROLE_CONFLICT` | 「已被「xxx」占用」 | 不写入；回读后角色不变 |
| 添加 | 候选人项目角色已被占用 | `ROLE_CONFLICT` | 同上 | 不写入 |
| 添加 | Agent 已在会话 | `ALREADY_MEMBER` | 「不能重复绑定」 | 不写入 |
| 添加/移出/改角色 | `setOperatorCanManage(false)` | `PERMISSION_DENIED` | 「无管理权限」 | 不写入 |
| 移出（未确认） | 目标 `inUse` 且 API 未带 confirmed | `AGENT_IN_USE` | 「正在参与当前协作」 | 不写入 |
| 移出（已确认） | 确认框点「确认移出」 | 成功 | 回读后消失 | 与快照一致 |

## Console 演示命令

```js
// 权限不足
window.__groupMemberMock.setOperatorCanManage(false)
// 恢复权限
window.__groupMemberMock.setOperatorCanManage(true)

// 通用失败注入（可选）
window.__groupMemberMock.setMockFailure('add')
window.__groupMemberMock.setMockFailure('remove')
window.__groupMemberMock.setMockFailure(null)
```

## 录屏脚本（可裁进 3–5 分钟总片）

1. 打开群设置 →「显示服务端快照」→ 指出 SQL 专家 `inUse: true`、管家/SQL 角色不同。
2. **角色冲突**：只选中「智能体管家」→ 角色改为「数据」→ 保存 → 出现占用提示 → 快照中管家仍是「编排」。
3. **权限不足**：Console 执行 `setOperatorCanManage(false)` → 再保存角色或移出 →「无管理权限」→ `setOperatorCanManage(true)` 恢复。
4. **使用中确认**：选中「SQL 专家」→ 移出 → 确认框出现 → 先点取消（仍在）→ 再移出并确认 → 回读消失，快照同步。
5. （可选）添加已占用角色的 Agent，或说明重复绑定文案。

口播要点：**操作 → Mock 服务端规则 → listMembers 回读**；冲突有解释、失败不脏界面。
