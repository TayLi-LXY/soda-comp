# 群成员管理 · 基础档验证说明（成员 = Agent）

## 产品口径

群成员只包含 **Agent**。加号从**历史会话**检索可编排 Agent，**不邀请真人**。

## 如何证明「界面 = 服务端」

1. 写操作先走 `addMember` / `removeMember`，成功后再 `listMembers`，用回读结果刷新 UI。
2. 失败时再 `listMembers` 对齐；回读失败则恢复操作前快照，并 `message.error`。
3. 可见证据：
   - 抽屉标题旁 **「显示服务端快照」**，对照列表与 JSON。
   - Console 过滤 `[groupMembers.mock]`。
   - `window.__groupMemberMock`（含 `searchCandidates` / `setMockFailure`）。

## 模拟失败

```js
window.__groupMemberMock.setMockFailure('add')
window.__groupMemberMock.setMockFailure('remove')
window.__groupMemberMock.setMockFailure(null)
```

失败注入为一次性。预期：报错后列表不脏。

## 手工验收清单

| # | 步骤 | 期望 |
|---|------|------|
| 1 | 进群聊 → `⋯` → 群聊设置 | 「群成员（Agent）」列表无假人；条目显示「来自：某会话」 |
| 2 | 顶栏输入关键词 | 只过滤**本会话**已入 Agent |
| 3 | 点「显示服务端快照」 | JSON 与名单一致，字段含 `originSessionTitle` |
| 4 | 点「+」 | Modal「从历史会话检索并添加 Agent」；候选项带来源会话 |
| 5 | Modal 内检索（如「库存」「画图」） | 列表按名称 / 角色 / 来源会话收窄 |
| 6 | 勾选确认添加 | 回读后出现在本会话；快照同步；仍带来源 |
| 7 | 选中 →「移出」 | 回读后消失 |
| 8 | `setMockFailure('add'|'remove')` 后再操作 | 报错；界面不脏 |
| 9 | 未选中点「移出」 | 提示先选择 Agent |
